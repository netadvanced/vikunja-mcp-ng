### AUDIT-001 — `vikunja_tasks list` reports a complete result from one clamped page

Same class as #225/#244, but on the **primary** path, not the per-project
fallback.

- No `page`/`perPage` → `FilterExecutor` synthesizes `per_page=1000`
  (`src/tools/tasks/filtering/FilterExecutor.ts:232-241`).
- Cross-project: one `GET /tasks` (`src/utils/filtering/RestCrossProjectFilteringStrategy.ts:90-113`).
  Vikunja clamps to `service.maxitemsperpage` (default 50). Response is
  `Found N tasks`, success, no `resultComplete: false`.
- Filtered single-project: `ServerSideFilteringStrategy.ts:46-88` (one
  `GET /projects/{id}/tasks?...&per_page=1000`). Unfiltered single-project
  auto-paginates in `ClientSideFilteringStrategy` and is **clean**.
- Multi-group `filter` + `done`: `done` is not folded into the server filter;
  post-filter runs on that truncated page (`FilterValidator.ts:279-281`,
  `FilterExecutor.ts:148-154`).

Same silent-complete class, weaker blast radius:

- `vikunja_notifications list` + `unreadOnly` filters client-side over one
  `GET /notifications` page (`src/tools/notifications.ts:159-172`) — can
  return “Retrieved 0” while unread exist later.
- `list-comments` is a single unpaged `GET /tasks/{id}/comments`
  (`CommentOperationsService.ts:62-68`).

### AUDIT-002 — templates persist file is not identity-keyed (oidc-http leak + wipe)

In-memory storage is `(issuer|sub)` via `getEffectiveSessionId`. Disk is one
flat `PersistedTemplateRecord[]` with **no identity field**
(`src/storage/templateFileStore.ts`).

- Hydrate (`templates.ts:99-104`) loads **every** record into the current
  session.
- Persist (`templates.ts:124-136`) writes **this session’s** list over the
  whole file (last writer wins).

Opt-in (`templates.persistPath` / `VIKUNJA_MCP_TEMPLATES_FILE`). Isolation
matrix row “Templates store isolation … persistence file rows keyed
distinctly” (`docs/OIDC-RESOURCE-SERVER.md` §3d / matrix) is **not**
implemented. Isolation tests do not cover persistence.

### AUDIT-003 — JWT-only gates still read the process-global `AuthManager`

REST is ALS-correct (`resolveEffectiveAuthManager`). Registration and several
per-call JWT gates still use the **closure** manager (`tools/index.ts:215`,
`users.ts:236`, `export.ts:212`, `admin.ts:140`, `user-deletion.ts:101`).

If `VIKUNJA_URL`/`VIKUNJA_API_TOKEN` auto-connect a JWT on the global
manager, JWT-only tools register for **every** oidc-http caller, including
`tk_*` vault users. Inverse: env token is API-token → JWT tools never
register even for a JWT-vaulted caller. Doc claim that the env token is
“ignored on the wire” is true for REST, false for the auth **surface**.

### AUDIT-004 — bulk `BatchProcessor` singletons do not serialize across requests

`processors.create|update|delete` in
`src/tools/tasks/bulk-operations-simplified.ts:72-125` are process
singletons. Each `processBatches` builds its **own** `Semaphore`. Intra-call
`maxConcurrency: 1` for creates still holds; N concurrent oidc-http
`bulk-create`s ⇒ N concurrent creates. That is the SQLite “database is
locked → breaker cascade” failure #116 was defending against, now
cross-tenant.

### AUDIT-005 — `auth-share` returns a live JWT in the MCP response

`src/tools/projects/sharing.ts:514-540` dumps `authResult` (includes
`auth.Token.token`) through `formatObjectData`. Tests expect it
(`tests/tools/projects/sharing.test.ts:416-427`). Not a deny-by-default mint
tool; contrast webhooks’ `redactWebhookCredentials`.

Related structural gap (not a demonstrated live secret, but the pipe is
open): thrown `MCPError.message` / tool text never go through logger
redaction; `SecureErrorHandler.sanitize` has no bare-`eyJ` rule
(`error-handler.ts:25-42`) unlike `redactSecretsInText`.

### AUDIT-006 — `vikunja_templates instantiate` claims success on partial work

`src/tools/templates.ts:536-598`: per-task create errors are `logger.warn`
only; label attach errors swallowed; message always `Project "…" created
from template "…"`; `createStandardResponse` defaults `metadata.success` to
`true`. `failedTasks` is in `data` only. `createdTasks: 0` still reads as
success. Violates pillar 4 (honest semantics) and the saga/partial-success
rule in `docs/ROADMAP.md` §1.

### AUDIT-007 — `list-members` hides a failed teams fetch as “0 teams”

`src/tools/projects/sharing-access.ts:759-812`: `users` rejection hard-fails;
`teams` rejection → `teams = []` with no error field. Message:
`… 0 direct team(s) …`, `success: true`. Caller cannot tell “no teams” from
“teams fetch failed”. Shares at least set `linkShares.available: false`.
